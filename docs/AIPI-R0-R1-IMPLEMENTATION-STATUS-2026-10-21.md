## Implemented

- Local task reconciliation now records a per-task metadata baseline and sends only changed title/status fields. A missing legacy baseline is accepted only when the cloud row matches its saved fingerprint. Conflicting changes are surfaced rather than overwritten. Old queued upserts with empty context are converted to safe patches or marked for review.
- New `apply_team_task_patch_operation` uses optimistic versions and idempotent operations. It preserves omitted description/revision fields, records project identity, and permits `in_review`. Direct authenticated writes to task rows and accepted-operation records are revoked.
- Installation registration requires GitHub user installation access, an identity linked to the AIPI user, and a matching App installation/account. Direct authenticated installation writes are revoked. Existing App-only grants are deactivated until reverified. GitHub PR publication is disabled until per-user repository capabilities exist.
- Local workspace groups open a five-tab workspace view with an all-projects filter. The same presentation module is built into the Team browser and IDE assets. Team uses its own data provider for shared projects/tasks and now reads published workspace graph nodes and edges into Explore and K-Maps. Unavailable source/diffs and runners have explicit states. The Team dashboard retains task creation, status edits, comments and evidence display.
- Upgrade pairing can select a workspace group, preview every project and resource category, bind all projects to one Team workspace, and persist the Team link on the local group. The IDE command also chooses the containing group. A fixed React/two-Python-service/external-endpoint/two-user/two-device/agent fixture defines the later acceptance scenario.
- Initial task import now queues title/status patches directly. Runtime-neutral workspace IDs, resource kinds, task aliases, entitlement states and permission intersection rules are defined in `packages/core/workspace-domain.mjs`.
- Additive migrations introduce per-workspace subscriptions, usage, membership, invitations and source-sharing policy. Security-definer snapshots, change pages, task context and decision search are filtered by workspace membership; direct writes to repository bindings require a broker.
- A GitHub App user OAuth exchange binds a verified GitHub user to an AIPI account through a service-role-only identity table. The broker rechecks installation and repository access for binding, pinned source reads and PR diff assessment. Team Explore can inspect a file at an immutable commit while companions are offline. PR assessment maps changed files to candidate graph nodes, affected projects and relevant checks while flagging Python evidence strength and unknown coverage.
- Repository binding now commits through `bind_team_repository_project`, which locks and rechecks the caller's workspace and account membership in the same transaction as the service-role write. A removed member cannot complete a binding from an earlier API check. The binding refuses to silently switch an existing project to a different GitHub repository.
- PR assessment re-reads the live GitHub PR base and head before comparing commits. It returns a conflict when the stored webhook revision is stale, before reading the diff or claiming any candidate impact. The cloud smoke test exercises stale and current heads.
- Direct authenticated graph reads and publish/review RPC calls are now revoked. Worker broker reads verify workspace membership and live repository grants; service broker writes recheck editor membership under row locks, so a queued graph write is denied after revocation. The Team PR report filters graph/receipts by current repository grants and leaves CI success unverified until accepted proof exists. Full export requires current grants for every bound repository. [Stand-in SQL and mocked route evidence](evidence/d0-d1-graph-broker-2026-10-22.json) does not close live platform authorization acceptance.
- Workspace-scoped task, context, evidence, comment, receipt, graph and PR row writes now hold shared locks on workspace and membership rows while checking editor authority. A repeatable two-session PostgreSQL test observed revocation wait 3.94 seconds for an in-flight write, followed by denial of a new write. The repository-binding broker has explicit minimal service-role project privileges. Team PR analysis now preserves old paths for renames/deletions and flags generated or uninspectable paths as incomplete; selected OpenAPI request constraints, path-level parameters and response optionality are compared, while unresolved references stay partial. [Fresh replay and focused evidence](evidence/d0-d1-write-and-diff-2026-10-22.json) remain stand-in, not live Supabase, acceptance.
- The shared task view now honors a task's multi-project `scope` when filtering by project. Team task reads include scope, so a task spanning the React and Python projects remains visible under either project filter.

## R2.6 companion session slice — 2026-10-22

The local companion now holds a separate sync session per Team organization. Pairing or reconnecting one account no longer stops another account's Realtime/cursor loop. A disconnect names the organization or a linked project and removes only that account's saved session. Status reports the selected project's account and lists active organizations; local task edits wake only organizations with newly queued operations. At startup, saved sessions for every linked organization restore asynchronously after the local dashboard begins listening, so cloud latency does not block free local use. A late restore cannot overwrite a newer sign-in or undo an explicit disconnect. Session-manager tests cover independent reconnect, selective wake-up, disconnect, shutdown and visible restore errors; an HTTP-level test checks scoped status and pending counts. The full `npm test` suite, local/CLI/verify bundle builds and TypeScript checks passed in this checkout.

This is one R2.6 implementation slice, **not R2 acceptance**. Actual account/session refresh and revocation, two-account browser and IDE journeys, full Supabase RLS/API tests, billing lifecycle, and R3/R4 data/source/proof parity remain open. The paid Team release gate in the product reset is unchanged.

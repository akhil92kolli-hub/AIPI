# AIPI D0 canonical sync and authorization acceptance plan

Date: 2026-10-22  
Status: planned; D0 remains open  
Parent: [capability delivery plan](AIPI-CAPABILITY-DELIVERY-PLAN-2026-10-21.md#d0--integrity-authorization-and-executable-baseline-r0r3-dependency)

## Outcome and present baseline

Two people on separate devices must see the same authorized task, context, decisions, evidence and workspace state after edits, retries, disconnects and reconnects. An access change must prevent new reads, writes, artifact access and event delivery at every public boundary. Local work must remain usable when Team is offline, with unsent changes visibly pending or conflicted.

The current outbox, cursor, snapshot, workspace membership and GitHub binding broker are a useful base. The local task reconciler fingerprints and patches **title and status only** (`packages/core/team-local-reconcile.mjs` and `team-sync-store.mjs`), while Team tasks carry description, revision set, context and related records. The Realtime client uses `team_change_events` as a wake-up and then pulls the cursor feed (`team-realtime.mjs`). Existing live evidence covers two signed-in users on selected REST/RPC routes and one four-second Realtime revocation observation. It does not cover two devices, private Storage, reconnect, full GitHub-rights revocation or all routes. [Live baseline](evidence/live-supabase-authorization-2026-10-22.json).

## Implementation sequence

| Slice | Deliverable | Acceptance before the next slice |
| --- | --- | --- |
| **0. Freeze the contract and threat model** | Inventory every local, IDE, Team, direct Supabase, Worker, Storage and Realtime read/write path. Classify each field and artifact by organization, workspace, repository and sensitivity. Specify which data stays device-local. Record the exact fixture identities and repositories. | Every exposed path has a resource owner, authorization predicate, expected deny response and test ID. No repository-derived source or graph payload is left in a workspace-wide direct API by accident. |
| **1. Canonical domain and identities** | Define versioned workspace, project binding, task, task context, decision, evidence, receipt and checkpoint schemas with stable qualified IDs. Keep Git remote identity separate from local checkout path. Preserve unknown fields in read/patch/write round trips. Add one projection contract consumed by local browser, IDE and Team. | A serialization round trip and status-only edit retain description, revision set, scope, decisions, evidence, receipts and unknown fields byte-for-byte where untouched. The same ID resolves to the same entity on both devices. |
| **2. Lossless operation log and convergence** | Replace title/status-only reconciliation with field-level versioned operations for every shared field and append-only entities. Persist operation ID, actor, device, base version, schema version and source pins before network send. Apply server writes atomically with change sequence; acknowledge duplicates by operation ID; represent concurrent same-field edits as reviewable conflicts. Make snapshot replacement and cursor advance one transaction; recover from expired cursors without dropping unsent operations. | Device A edits rich context offline; B edits a different field; A reconnects and both converge. Same-field conflict is shown rather than overwritten. Duplicate, delayed and out-of-order operations apply once. Crash before/after server commit replays safely. Unknown fields survive an older client. |
| **3. Repository-rights boundary** | Keep current GitHub user-to-AIPI identity link and App installation checks; centralize a fresh per-request repository authorization decision for Worker source, diff, graph, impact, task context, receipts, PR and export routes. Recheck user access **and** current App installation scope for every bound repository referenced by the result. Prune unauthorized nodes before traversal and suppress names/counts/relationships that infer private repositories. For direct Supabase REST/RPC or Realtime paths that cannot check live GitHub rights, serve only repository-neutral metadata or revoke direct grants and route repository-derived reads through the broker. Never use a cached claim alone as current GitHub authorization. | With AIPI membership unchanged, remove the user's GitHub access, then reduce/remove App scope separately. Every repository-derived read/write and aggregate denies or redacts immediately on a fresh request; a permitted sibling repository remains usable. A queued write cannot commit after revocation. |
| **4. Private artifact storage** | Add a private Team artifact bucket and metadata mapping immutable artifact ID/hash to workspace and repository scope. Use server-mediated upload/download with membership and live repository checks, bounded paths/sizes, digest verification and no public URLs; keep the service key server-only. If signed download URLs are used, their validity window is an explicit revocation limit; use brokered downloads where immediate revocation is required. Verify direct Storage list/read/insert/update/delete policies, including upsert semantics, with two users. | User B can upload/download an authorized artifact. A third user, removed workspace member and GitHub-revoked member cannot list, read, overwrite or delete it through direct Storage APIs or the Worker. Previously issued URLs are tested against the stated expiry guarantee. No artifact bytes or path leak through snapshot, event or export. |
| **5. Realtime reconnect and cache invalidation** | Keep Realtime as a notification, never the source of truth. On initial join, reconnect, token refresh, permission change and sequence gap, reauthorize and pull the cursor feed or a filtered snapshot. Make events payload-minimal until repository scope can be enforced; do not trust a workspace-wide event body as an access grant. On 403, clear or quarantine unauthorized cached cloud entities and stop outbound writes while preserving local-only data and a visible conflict/export state. | After a forced WebSocket drop, both devices catch up from the authoritative feed. Duplicate/missed events do not alter final state. After workspace or repository revocation, an already connected client and a reconnecting client receive no forbidden payload, cannot fetch it, and cannot resubmit queued writes. |
| **6. Cross-surface product acceptance** | Connect Home, Explore, Tasks, K-Maps and Tools in local browser, IDE and Team to the same canonical provider, IDs, status reasons and sync state. Remove the parallel Team task-detail state once parity is proved. | On two devices, a rich task and its decisions, source pins and receipts match across surfaces. Pending, offline, conflict, restricted and stale states are visible. Local mode works with Team unavailable. |

The order is deliberate: the domain contract and read boundary must be settled before treating an event stream or Storage bucket as safe. Current workspace membership alone is insufficient for a mixed-repository workspace because GitHub rights can change independently.

## Acceptance fixture and permission matrix

Use a **fresh disposable Supabase project** with all migrations and pgTAP suites, plus a separate legacy-upgrade fixture. Do not alter production fixtures for these tests. Create one organization, one workspace containing React, Orders and Billing repositories, two authorized users (A and B), a third user (C) without workspace access, two independent device stores, one agent/runner identity and private source/evidence artifacts. Give B access to React and Orders initially, but not Billing. Test both unbound workspace metadata and repository-bound data. Capture exact migration versions, schema/client revisions, operation IDs, cursors and sanitized responses.

| Event | Direct REST/RPC | Worker/source/graph/export | Private Storage | Realtime and reconnect | Local/IDE cache and outbox |
| --- | --- | --- | --- | --- | --- |
| A and B authorized | Same permitted canonical records; writes have expected versions | Permitted repositories only; no hidden cross-repo edge | Scoped upload, list and download work | Both devices converge by cursor | Matching IDs, content and status |
| C never a member | Deny workspace rows and RPCs | Deny before repository access | Deny all object operations | No subscribed payload | No Team cache or writes |
| B workspace membership revoked | Deny read/write, including queued write race | Deny all workspace routes | Deny list/read/write/delete | Existing channel and reconnect reveal no new payload | Purge/quarantine Team cache; retain local-only work without automatic upload |
| B loses GitHub user repository right, but remains workspace member | Repository-derived direct data unavailable | Deny/redact affected repository and inferred edges; sibling access survives | Deny affected repository artifacts | No repository-derived body; pull is filtered | Previously cached repo-derived Team content becomes restricted; queued writes stop |
| App installation loses repository scope or is suspended | Same repository-derived rule | Deny even if B's user grant remains | Deny affected artifacts | Reconnect and feed remain filtered | Mark scope restricted and require reauthorization |
| Token/session expires or user switches account | Reject stale identity; fresh sign-in re-evaluates | Reject old identity and mismatched GitHub account link | Deny stale credential | New join uses fresh identity and cursor | No cross-account cache bleed |

For every row, exercise direct table reads, callable RPCs, snapshot/change feed, source/diff, graph/impact, PR/report, task/context/evidence/receipt write, organization export, Storage object operations and both existing and new Realtime connections. Test request already queued before revocation, concurrent write/revocation ordering, and post-revocation retry. Do not infer authorization from the UI hiding a control. A direct API 200 with private rows, a payload-bearing event after revocation, or a stale signed URL exceeding the declared guarantee fails D0.

## Test harness and evidence

Extend `scripts/live-supabase-authorization-acceptance.py` and `scripts/live-supabase-realtime-probe.mjs` for the matrix; add a two-device harness around `TeamSyncStore`, `syncTeamOnce` and `startTeamSyncSession`. Keep API tokens and fixture credentials in ephemeral process memory; redact them from logs. Use real Auth sessions, PostgREST, Storage and Realtime against the disposable project. Use a controlled GitHub App installation and two test repositories for **current** user/App-scope revocation; mocks may test error branches but cannot close that acceptance row. Use a packaged local companion and IDE instance for final parity, with a second physical or isolated virtual device for independent disk state.

Record one evidence bundle under `docs/evidence/` containing: migration/pgTAP results; route inventory and expected/actual status; sanitized pre/post-revocation responses; artifact hashes; Realtime join/drop/rejoin timestamps and cursor sequences; two-device canonical snapshots and field-level diff; offline/conflict/retry trace; exact test commands; cleanup confirmation; unresolved limits. Link it from both [delivery](AIPI-CAPABILITY-DELIVERY-PLAN-2026-10-21.md) and [executive](AIPI-EXECUTIVE-CAPABILITIES-UX-PLAN-2026-10-22.md) plans.

**D0 passes only when** every matrix row passes on the intended adapters, the two-device canonical snapshots match after convergence, no rich field or unknown field disappears, no forbidden data is reachable through a direct endpoint or event, and the local product remains usable offline. Keep D0 open for any skipped route, mocked GitHub revocation, missing private bucket, untested reconnect or unresolved artifact URL lifetime.

## Supabase design references checked for this plan

- [Storage access control](https://supabase.com/docs/guides/storage/security/access-control): private object operations are governed by `storage.objects` policies; upsert requires SELECT and UPDATE as well as INSERT.
- [Private Storage serving](https://supabase.com/docs/guides/storage/serving/downloads): private objects require authenticated download or a time-limited signed URL.
- [Realtime Postgres Changes](https://supabase.com/docs/guides/realtime/postgres-changes): publication, RLS and subscription behavior require live testing.
- [Realtime authorization](https://supabase.com/docs/guides/realtime/authorization): Broadcast/Presence channel permission is assessed at join; it is separate from Postgres Changes row filtering.
- [Realtime schema change](https://supabase.com/changelog/realtime-schema-locked-down-against-modification): migrations must not create or alter objects in the `realtime` schema; RLS policies on `realtime.messages` remain allowed.

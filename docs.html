01 · Architecture

Cloud-rendered. Locally executed.

The website and dashboard shell are delivered from Cloudflare. When you open AIPI, your browser connects directly to the companion at 127.0.0.1:49152. Repository scans, API calls, response bodies, credentials, logs, and evidence never need to leave your machine.

Cloudflare UI→Browser→Local companion→Repository + APIs

02 · Commands

The commands you need.

The companion is published on the public npm registry. Run these commands from the project root; no registry setup is required.

npx @akhil92kolli-hub/aipi-companion initDetect source roots, write .aipirc.json, and inject IDE MCP config.
npx @akhil92kolli-hub/aipi-companion open --app https://aipi.website/dashboard/Start or reuse the daemon and open the connected cloud dashboard.
aipi daemonRun the loopback dashboard server directly when you need a persistent local engine.
aipi mcpRun the thin stdio MCP client; it reuses or starts the daemon.
aipi dev --app http://localhost:8788/dashboard/Use the local dashboard during website development.

03 · MCP setup

Give your agent a local evidence layer.

Add AIPI to your MCP client. The server uses stdio, so the agent can request repository-aware discovery, diagnosis, and verification without exposing a listening MCP endpoint.

{
  "mcpServers": {
    "aipi": {
      "command": "aipi",
      "args": ["mcp"]
    }
  }
}

05 · Troubleshooting

When the dashboard says disconnected.

Check the daemon

Run aipi daemon or aipi open --app https://aipi.website/dashboard/. Confirm that http://127.0.0.1:49152/health responds. If that port is busy, AIPI automatically tries the next ports through 49160.

Refresh the session

Close the dashboard tab and run aipi open --app https://aipi.website/dashboard/ again. The new launch hash contains a fresh short-lived token.

IDE cannot find MCP

Run aipi init again from the project root. It writes the aipi entry to local Cursor and VS Code MCP configuration. Restart the IDE after changing its MCP settings.

Browser blocks loopback access

Use the dashboard from the same browser profile, allow the local-network prompt, and keep the daemon bound to 127.0.0.1. A secure outbound bridge is planned for stricter environments.

Recommended path

One setup command, then automatic local-first workflow.

npx @vmise/aipi-companion init
npx @vmise/aipi-companion open --app https://aipi.website/dashboard/

Run both commands from your project root. init detects your app and wires IDE MCP settings; open starts or reuses the local daemon and opens the connected dashboard.

01 · Install

Install the local companion

npx @vmise/aipi-companion init
npx @vmise/aipi-companion open --app https://aipi.website/dashboard/

The companion is published on npm and binds to loopback by default. It does not open your project to the public internet.

02 · Connect your IDE

Register the local MCP server

{
  "mcpServers": {
    "aipi": {
      "command": "aipi",
      "args": ["mcp"]
    }
  }
}

Codex or another supported IDE uses MCP over stdio. The agent remains in control of repository changes.

03 · Connect

Open the cloud-rendered dashboard

  1. aipi init writes .aipirc.json and IDE MCP settings.
  2. aipi open starts or reuses the loopback daemon.
  3. A short-lived token is placed in the dashboard hash.
  4. The browser talks directly to 127.0.0.1; API work remains local.

The current release uses direct authenticated loopback. An optional outbound pairing bridge is a later enterprise phase.

04 · Connection token

How the dashboard connects

  1. The local daemon creates a random, short-lived sec_... token when it starts.
  2. aipi open puts only the local port and token in the launch hash: #port=49152&token=sec_....
  3. The hosted dashboard reads the hash in your browser and keeps the token in temporary session storage.
  4. Browser requests go straight to http://127.0.0.1:<port> with an Authorization: Bearer header.

Cloudflare delivers the UI but does not proxy the token, source code, credentials, API traffic, response bodies, logs, or project evidence.

05 · MCP and daemon

One local engine for every client

{
  "mcpServers": {
    "aipi": { "command": "aipi", "args": ["mcp"] }
  }
}

aipi mcp is a thin stdio client. It reuses the daemon started by the dashboard or starts one silently when an IDE calls it.

06 · Prerequisites

What you need

✓ Node.js 20 or newer

✓ A local JavaScript or TypeScript project

✓ Cursor, Windsurf, Claude Desktop, or another MCP client (optional)

✓ No account, database, or Docker required for the local core

07 · Data boundary

✓ Logs and evidence stay in the local workspace
